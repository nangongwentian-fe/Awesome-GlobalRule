# memory-scoping.md

## 1. 目标

本文件用于定义经验沉淀时的作用域判断、写入位置选择和强制路由规则。  
经验沉淀必须先判断作用域，再决定写到哪里。  
禁止“先默认写根级，再靠人工纠正”。

---

## 2. 核心原则

1. 经验沉淀必须先判断作用域：局部 / 模块 / 项目 / 全局。
2. 默认采用“写低不写高”原则：能写在更近目录，就不要写到更高层级。
3. 根级 `AGENTS.md` 不是默认落点，只是项目级经验的最上层入口。
4. 局部经验、模块经验应优先写入更接近实际生效位置的目录。
5. 作用域不明确时，禁止把经验直接上提到高层级文件。

---

## 3. 四级作用域定义

### 3.1 局部经验

满足以下任一条件，通常应判定为局部经验：

- 只对当前文件生效
- 只对当前目录生效
- 只对某个页面生效
- 只对某个组件生效
- 只对某条业务链路生效
- 只对某个弹窗、卡片、表格、路由链路生效

写入位置：
- 当前目录下的 `AGENTS.md`

### 3.2 模块经验

满足以下任一条件，通常应判定为模块经验：

- 对某个业务子系统普遍成立
- 对某个功能模块下的大多数页面成立
- 对某个目录树内的实现方式具有稳定指导意义

写入位置：
- 该模块根目录下的 `AGENTS.md`

### 3.3 项目经验

满足以下任一条件，通常应判定为项目经验：

- 对仓库中的大多数目录成立
- 属于团队共通约定
- 与全局编码偏好、仓库级结构、全局经验机制有关

写入位置：
- 项目根级 `AGENTS.md`

### 3.4 全局经验

满足以下任一条件，通常应判定为全局经验：

- 跨多个项目稳定适用
- 与个人长期工作方式或通用协作习惯有关
- 不依赖当前仓库具体结构

写入位置：
- 当前工具支持的全局记忆系统
- 或全局经验文件

---

## 4. 强制路由规则

1. 经验沉淀时，必须优先尝试判定为局部经验。
2. 只有当局部经验明显超出当前目录、当前页面、当前链路范围时，才允许继续上升判断为模块经验。
3. 只有当模块经验明显对整个仓库大多数目录都成立时，才允许上升为项目经验。
4. 只对单个页面、单个组件、单个目录、单条业务链路生效的经验，禁止写入项目根级 `AGENTS.md`。
5. 如果当前逻辑目录下还没有 `AGENTS.md`，且发现的经验明显只作用于该目录或该模块，则应先在该目录创建局部经验文件，再写入经验。
6. 根级经验文件中若开始出现具体页面名、组件名、目录名、路由名、链路名等明显局部细节，应优先判定为“写入位置过高”。

---

## 5. 禁止使用的错误分类方式

以下分类方式会把局部经验错误推高，应避免：

1. 只问“这条经验是否与当前项目相关”
2. 只分“项目经验 / 全局经验”
3. 只根据当前会话所在仓库判断“既然在这个项目里讨论，那就记到项目根”
4. 只因为经验是“本次探索出来的”就默认写入根级 `AGENTS.md`

这些做法都会导致根级文件迅速膨胀，不符合渐进式披露原则。

---

## 6. 正确的确认问题

当作用域存在不确定性时，应优先这样问：

1. “这条经验只在当前目录/当前模块生效，对吗？”
2. “这条规则是当前子系统内通用，还是整个项目都通用？”
3. “这条经验更适合写在当前模块目录下，还是应该上升为项目级规则？”
4. “这条经验是局部链路经验，不是仓库级规则，对吗？”

禁止优先这样问：

- “这条经验是否与当前项目相关？”

---

## 7. 创建局部 AGENTS 的时机

出现以下任一信号时，可以判定当前目录适合创建局部 `AGENTS.md`：

1. 同一目录下的问题被重复探索两次及以上
2. 同一模块反复出现固定坑点
3. 某条业务链路需要靠经验才能快速定位
4. 某目录存在稳定业务逻辑或特殊实现约定
5. 后续修改该目录时，明显需要先读一遍历史经验

---

## 8. 何时读取本文件

以下场景应主动读取本文件：

1. 准备沉淀新经验时
2. 不确定经验该写在哪个目录时
3. 发现 Agent 习惯性把经验写进根级文件时
4. 准备新建局部 `AGENTS.md` 时
5. review 经验文件时

---

## 9. 作用域判断示例

### 示例 1
经验内容：
“`Secure/Config` 页面中，旧版访问授权编辑按钮走 `AuthRuleEditModal`，新版链路走 `acc-ctrl -> PsmClusterDetailCard`。”

判断：
- 只作用于单条业务链路
- 与具体页面、组件、链路名强相关

结论：
- 局部经验
- 应写入 `Secure/Config` 对应目录下的局部 `AGENTS.md`

### 示例 2
经验内容：
“当前应用所有弹窗表单都使用同一套提交与关闭逻辑封装。”

判断：
- 对当前应用多数模块成立
- 不是某个单独目录独有

结论：
- 模块经验或应用级经验
- 写入对应应用根目录 `AGENTS.md`

### 示例 3
经验内容：
“默认使用中文回答；改代码前先阅读相邻实现并保持最小修改范围。”

判断：
- 仓库级通用约束

结论：
- 项目经验
- 可写入项目根级 `AGENTS.md`
