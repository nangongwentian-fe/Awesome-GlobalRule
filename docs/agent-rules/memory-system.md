# memory-system.md

## 1. 目标

本文件用于定义经验沉淀系统的目标、触发时机和基本行为。  
经验沉淀的本质是减少重复探索、重复纠正和重复解释，让 Agent 能持续复用已经确认过的有效结论。

---

## 2. 核心原则

1. Agent 应主动寻找并复用已有经验，而不是每次都从零重新探索。
2. Agent 也应在合适时机主动沉淀新的有效经验。
3. 经验沉淀的目标是提升后续任务质量与上下文延续能力，而不是机械堆积规则。
4. 经验只有在未来大概率还会复用时才值得写入。
5. 一次性问题、临时上下文、偶然性偏好，不应进入经验系统。

---

## 3. 什么算“值得沉淀的经验”

以下内容通常值得沉淀：

1. 用户明确要求“记住”的规则、约定、判断标准
2. 用户解释的重要业务逻辑、领域规则、数据约束
3. 重复出现的 review 反馈
4. 某类问题的稳定根因
5. 已验证的最佳实践或可靠排查路径
6. 某个模块中反复使用的定位方式
7. 未来再次处理该模块时能显著节省时间的信息

---

## 4. 什么不该沉淀

以下内容通常不应沉淀：

1. 只在当前对话短期有效的信息
2. 一次性的临时判断
3. 还未确认的猜测
4. 未来很可能马上变化的状态信息
5. 只是当前任务背景，但不具有复用价值的叙述
6. 明显属于用户当下偏好但不稳定的内容

---

## 5. 何时主动寻找已有经验

开始任务前，如果出现以下任一信号，应主动寻找已有经验：

1. 当前模块曾经被探索过
2. 同一类问题以前出现过
3. 当前链路中存在明显历史坑点
4. 当前任务与某次历史问题高度相似
5. 当前目录已经有局部 `AGENTS.md`

---

## 6. 何时主动沉淀新经验

当出现以下任一情况时，应主动判断是否值得沉淀：

1. 用户明确要求“记住”
2. 用户解释了一段重要项目逻辑
3. 用户重复指出同一类问题
4. Agent 找到了此前反复出错问题的稳定正确做法
5. Agent 发现一个能显著减少后续探索成本的定位信息
6. 当前目录明显已经出现“重复踩坑 -> 重复解释 -> 再重复探索”的模式

---

## 7. 经验沉淀的行为要求

1. 沉淀经验前，先判断作用域。
2. 先查重，避免重复新增相似经验。
3. 优先写成可执行规则，不写成长篇背景叙述。
4. 若旧经验已存在，应优先合并、修订或替换。
5. 经验写入后，后续任务应主动复用，而不是等用户再次提醒。

---

## 8. 经验沉淀后的使用方式

1. 进入相关目录时，应优先检查是否已有局部经验文件。
2. 如果当前任务明显受某条历史经验影响，应在执行中体现已应用该经验。
3. 如果某条经验帮助减少了探索成本，可在合适时机简要说明已应用。
4. 若经验已经失效，则应更新或删除，而不是继续沿用。

---

## 9. 与其他文件的关系

1. 本文件负责说明“为什么要沉淀经验、什么时候沉淀”。
2. 经验写到哪里，由 `memory-scoping.md` 负责。
3. 经验过期后如何修改、删除、下沉，由 `memory-update-and-pruning.md` 负责。

---

## 10. 何时读取本文件

以下场景应主动读取本文件：

1. 准备沉淀经验时
2. 不确定某段信息是否值得记住时
3. 发现自己在重复探索相同问题时
4. 用户要求“记住”某条规则时
